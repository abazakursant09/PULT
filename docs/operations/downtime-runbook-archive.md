Ниже сохранены исходные примеры, а не подтверждённая конфигурация Пульта.

## 1. Проверить сервер

Исходный совет: убедиться, что сервер запущен и отвечает.

```text
ssh user@your-server-ip
systemctl status nginx
systemctl status uvicorn  # или pm2 status
curl http://localhost:8000/api/health
```

## 2. Проверить необходимость перезапуска

Исторические примеры изменяют состояние системы. Не выполнять без
подтверждения причины, целевого стенда, разрешения и плана восстановления.

```text
systemctl restart uvicorn
systemctl restart nginx
# Или через PM2:
pm2 restart all
pm2 logs --lines 50
```

## 3. Проверить базу данных и место на диске

```text
# SQLite (дев):
ls -lh business_pult.db
# PostgreSQL (прод):
psql -U postgres -c "SELECT 1"
df -h  # проверить место на диске
```

Путь к БД и пользователь PostgreSQL — исторические примеры, не действующие
реквизиты. Не публиковать данные БД или секреты из диагностического вывода.

## 4. Проверить логи

```text
journalctl -u uvicorn -n 100 --no-pager
tail -f /var/log/nginx/error.log
pm2 logs --err --lines 50
```

Перед передачей фрагментов логов удалить токены, персональные данные и ключи.

## Исторические оценки времени

На странице были указаны: перезапуск — 2–5 минут; проблема с БД — 10–20 минут;
проблема хостинга — 30 минут–2 часа. Эти оценки не подтверждены, не являются
RTO и не должны использоваться как обещание восстановления.

Отметки чек-листа и старое сообщение «сайт должен работать» не являются
доказательством восстановления. Нужны фактические проверки здоровья,
доступности и целостности данных по отдельному проверенному регламенту.
