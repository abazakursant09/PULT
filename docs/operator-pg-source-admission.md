# Dormant synthetic PostgreSQL source envelope

This additive package approves no working database, credentials, deployment,
enrollment, journal append, purge, restore or public launch. It prepares a fixed
source envelope for the accepted read-only reviewer and process-stop mechanism.
The old eleven-source SYNTHETIC profile and backend adapter stay unchanged; all
prior gates remain mandatory. Rollback leaves this package unused, not claims reset.

The DRAFT source catalogue has a different format from an operational envelope.
Its hashes are not independent approval. Catalogue hashes normalize checkout CRLF
to LF for assembly only; the actual loader hashes exact installed bytes.

## Separate approvals

The fixed OS-trusted bootstrap accepts a new bounded canonical envelope with an
independently supplied SHA-256. It binds the old profile's path/digest and exactly
fifteen source roles: the old eleven, accepted backend policy/reviewer, and this
bootstrap/runtime pair. It does not admit test helpers, a fault fixture or a
caller-selected handler. All source bodies are captured before application code
executes, with protected descriptor-relative paths, ownership, single links,
no POSIX ACLs and stability checks. Symlink ancestors and same-byte inode swaps
are refused. The old loader continues to reject the new format/mode.

Archive/content hashes are verified completely before execution. Their exact
read-only file and parent descriptors then have one owner: the returned Admission.
Later guards still verify full content hashes, file stamps, ACLs and path links
through those exact descriptors. They avoid reopening/re-walking hundreds of
paths; unchanged owned-directory stamps preserve the exact installed inventory.
Byte changes are refused even if size and metadata are unchanged. In-memory
captured source hashes remain checked too. Native import paths retain the stated
trusted-root/OS boundary; this is not hostile-root protection.

Admission is one-shot and closeable/context-managed. Root `run()` consumes it and
returns no receipt if descriptor closure is uncertain. The actor closes its
source descriptors before CLOSED and on failure; poisoned close is not retried
or turned into success. A failed close requires process termination/review.

Root-owned sticky shared ancestors, such as `/tmp`, are checked by device/inode,
type, owner/group, mode/sticky protection, retained descriptor/path identity and
ACL rejection. Unrelated sibling churn does not require their directory-content
timestamps, size or link count to remain fixed. Full file stamps/hashes and full
owned release/dependency directory stamps remain exact; this does not admit
source, permission, ownership, ACL or path substitution.

The envelope binds exactly four accepted, SHA-256-pinned Linux CPython3.12 wheels.
Their verified archive bytes derive the complete installed-file inventory;
unknown, missing, changed or extra files/directories cannot become dependencies.
All installed directories and files are root-protected and checked again before
imports. No repository/site/bytecode fallback is permitted. Native extensions
reopen these protected paths under trusted root, kernel and fixed OS/runtime
assumptions; this is not a defence against hostile root or compromised libraries
in the trusted operating system.

Only an artificial binding is accepted: a Unix socket below an owned temporary
`/tmp/pult-op-pg-*` fixture, matching synthetic database/role/application tokens,
and a fixture-only generated password. No TCP URL, environment, credential-store
lookup or working-key provider exists. Naming and a fixture flag are restrictions
under trusted-root operation, not independent provenance of a production server.
The actual native proof must separately establish its newly owned synthetic DB.

## Fixed dispatch and process lifetime

The root API loads the approved captured runtime. Its private deterministic
adapter retains the accepted PID1/setpriv command and replaces only its fixed
worker suffix with the newly approved bootstrap and envelope digest. No request
selects argv, environment, paths, SQL, factory, fault mode or timeout. The parent
checks the actual worker argv, original controller, all kernel UID/GID/capability
sets and exact unit policy before GO. The old permanent claim, no-retry rule,
15-second runtime, 2-second stop limit, EOF, reaping and empty-cgroup checks remain.

Only the capability-free actor imports third-party code. It creates a dedicated
asyncpg/NullPool engine with hidden parameters, fixed connection settings and a
private diagnostic sink retaining the accepted sticky cleanup-failure latch.
The unchanged reviewer closes its native connection before an observation; the
worker also disposes its owned engine and closes sockets before CLOSED.

A client observation is early non-admitting evidence. A distinct outer receipt
binds both the new envelope approval and old profile digest and succeeds only
after the complete inner supervision result and cleanup. An inner UNKNOWN,
missing/false cleanup field, wrong approval, incomplete digest, uncertain stop
or dead controller cannot become outer success. All mutation flags remain false.

## Proof boundary

Portable shape/framing/receipt tests do not prove Linux descriptors or PostgreSQL.
A mandatory native proof must use the direct new entry path and a newly owned,
Unix-only, networkless pinned PostgreSQL fixture. It must verify reader absence
and unchanged application rows BEFORE server teardown, exact child argv and
resource cleanup. Old eight-case PG, eleven-case offline and six-case joint gates
remain separate mandatory evidence, not replaced by this new proof.

The new native inventory requires eighteen cases and zero skips: one direct
approved PG observation; wrong approval/mode/legacy envelope; changed source or
native extension; extra dependency file or empty directory; same-byte legacy
profile/dependency replacement; controlled shared-ancestor churn; and actual
source symlink, hardlink, mode, owner and POSIX-ACL refusals. Same-inode source and
native-extension byte changes with preserved size/mtime are refused after load.
Only the authorized case starts a real PG fixture and must independently prove
no readers and unchanged rows before teardown. The seventeen intake-only cases
must not start a DB or call runtime.run(); their database observation fields are
null, not manufactured PASS. A fake binding there is input-shape evidence only.
Both kinds retain exact owned-unit/source-descriptor cleanup requirements. This
avoids seventeen unnecessary initdb cycles without changing worker-runtime or
stop policy, and does not substitute for the real PG case.
The shared test fixture's bounded initdb/readiness budget is separately extended
from 20 to 60 seconds after repeated preparation-only timeouts. It verifies the
same pinned image, mounts, role and seed before admitting any worker; no retry or
partial setup is accepted. The operator's 15-second runtime and 2-second stop
deadline remain unchanged. This is a test-fixture change, not a new DB authority.
Churn is an intake-only
case, not a second PG review or a mutation permit. Diagnostics may identify owned
temporary scopes and technical unit IDs. Runtime failures expose only fixed
stages/types; test basenames and line numbers are structural evidence. No raw
exception values, SQL, binding/credential bodies or working paths are echoed.
The direct entry must be untraced and unprofiled. Test-owned root timing witnesses
do not change payloads, argv, callbacks, code selection or outcomes.

Even an approved synthetic source closure is not production PG source admission,
a database anti-clone identity, fresh head, live erasure lease or authority to
change data. Actual placement/authentication, working credentials, independent
identity storage, retention of safety state and all mutation gates remain open.
Normal 30/7/14-day recovery/backup/diagnostic TTLs do not decide safety-state TTL.
