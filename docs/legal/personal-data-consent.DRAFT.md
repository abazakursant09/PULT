## Требования к реализации (сейчас НЕ выполнены — блокер)

Факт по коду: согласие собирается только на фронтенде и **на сервер не передаётся** — запрос регистрации содержит лишь `email/name/password/ref_code` (`frontend/lib/api.ts:1265-1269`, `backend/schemas/auth.py:7-11`), у модели `User` нет поля согласия. Этого недостаточно.

1. Checkbox по умолчанию выключен и не объединён с Пользовательским соглашением или рекламой.
2. Рядом доступны полный текст согласия и Политика.
3. **Backend сохраняет** user ID, версию текста согласия, UTC-время, способ принятия и необходимые доказательства. Текущий frontend-checkbox без серверной записи недостаточен для доказывания согласия.
4. Рекламная рассылка, автопубликация отзывов, Telegram и иные самостоятельные цели требуют **отдельных** согласий/действий.
5. Нельзя писать «продолжая пользоваться, вы соглашаетесь» вместо доказуемого явного действия там, где основанием является согласие.
