# DNS runbook — pult-os.ru (NOT APPLIED — dormant reference only)

Status: **NOT APPLIED.** No DNS record is created by this document. It is a checklist to run manually at
Inal-approved activation, **after** the domain gate `DOMAIN VERIFIED: pult-os.ru зарегистрирован;
идентификация подтверждена.` and after the target IP/mail provider are known. All values below are
placeholders (`<APP_IP>`, `<MX_HOST>`, `<...>`) — never real IPs, keys, or selectors in the repo.

## Preconditions (all manual, Inal)
- Domain gate confirmed; registrar admin identification via Госуслуги complete.
- Server purchased + hardened (separate gate); app reachable at `<APP_IP>` over HTTPS.
- Mail provider chosen (mailboxes for support@/privacy@/security@ — separate mail gate).

## Records to create (at activation only)
| Record | Name | Type | Value | Note |
|---|---|---|---|---|
| apex | `pult-os.ru` | A | `<APP_IP>` | primary origin |
| www | `www.pult-os.ru` | CNAME or A | `pult-os.ru` / `<APP_IP>` | redirect to apex (or apex to www — pick one canonical) |
| TLS | — | — | ACME/Let's Encrypt for apex + www | issue AFTER A record resolves; HSTS only after verified |
| MX | `pult-os.ru` | MX | `<MX_HOST>` (priority) | only when mail provider ready |
| SPF | `pult-os.ru` | TXT | `v=spf1 include:<MAIL_PROVIDER> -all` | strict `-all` |
| DKIM | `<selector>._domainkey.pult-os.ru` | TXT | `<DKIM_PUBLIC_KEY>` | key generated by mail provider (not stored in repo) |
| DMARC | `_dmarc.pult-os.ru` | TXT | `v=DMARC1; p=quarantine; rua=mailto:security@pult-os.ru` | start `p=quarantine`, raise to `reject` after monitoring |

## Hard checks before/after
- **No wildcard** `*.pult-os.ru` record. No unexpected/extra records. No dangling CNAME.
- TLS issued only after the A record resolves; verify cert chain + auto-renew.
- SPF `-all` strict; exactly one SPF TXT (no duplicates).
- Verify apex, www, MX, SPF, DKIM, DMARC resolve as intended; then send/receive a mail test.
- Confirm no legacy `biznes-pult.ru` records are copied over by mistake.

## Rollback
Remove the added records (apex/www/TLS/MX/SPF/DKIM/DMARC); revert `FRONTEND_URL` to the previous origin;
the previous domain/contact stays live meanwhile. DNS rollback touches only the registrar zone — it does
not affect the database, the backup bucket, or any Selectel storage resource.

## Fail-closed
If any precondition or check fails → STOP, do not proceed, keep the current live domain/contact. This
runbook grants no automatic execution; every step is a manual Inal-approved action.
